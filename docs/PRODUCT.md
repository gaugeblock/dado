## 1. Problem Statement & Market Context

When AI coding agents (Claude Code, Cursor, Cline, Windsurf) are asked to implement software components, they face three major bottlenecks:

1. **Massive Token Waste on Boilerplate:** Generating standard architectural patterns (Axum handlers, CLI subcommands, database transactions, gRPC services) forces the LLM to output 80–120 lines of predictable boilerplate text token-by-token. This wastes 85%+ of the model's context budget on code that is structurally deterministic.
2. **Brittle Text Substitution:** Using text templating engines (Jinja/Handlebars) or naive search-and-replace frequently produces invalid syntax, mismatched braces, or missing import statements that break compiler verification.
3. **Cross-Language Type Divergence:** Manually synchronizing backend Rust structs with frontend TypeScript interfaces leads to silent schema drift and production deserialization errors.

`dado` eliminates these failure modes by providing a deterministic, Tree-sitter validated AST pattern engine with explicit typed holes.

## 2. Target Personas & User Journeys

### Persona A: Neurosymbolic Orchestrator (`joiner`)
- **Needs:** Pre-verified AST templates where all structural boilerplate is fixed, exposing only typed holes for semantic code generation.
- **Workflow:** Selects a matching `dado` pattern (System 1 routing), queries hole constraints, constrains the model with `batten`, and renders the completed AST without manual syntax repair.

### Persona B: Autonomous AI Coding Agent
- **Needs:** Instant retrieval of verified idiom packs and structural mixins (tracing, timeouts, transactions) without needing to recall complex framework boilerplate.
- **Workflow:** Calls `dado_inspect_pattern` to view typed hole signatures, generates the business logic values, and invokes `dado_render` to produce production-grade code.

### Persona C: Full-Stack Systems Engineer
- **Needs:** Guaranteed alignment between backend database entities and frontend API client schemas.
- **Workflow:** Runs `dado contract` in build scripts to emit synchronized Rust serde structs and TypeScript Zod schemas from a single shared specification.

## 4. Key Metrics & Success Criteria

* **Token Budget Reduction:** `>85%` fewer tokens generated by LLMs on structural code synthesis tasks.
* **Syntax Invariance:** `0%` Tree-sitter `ERROR` or `MISSING` nodes in rendered AST code.

* **Offline Independence:** `100%` functionality with zero network calls and embedded starter packs.
